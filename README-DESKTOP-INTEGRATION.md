# MCGI Bible Broadcaster Pro — Windows Desktop Integration

This patch wraps the existing Bible broadcast server and web modules in Electron. It does not rewrite the Operator, Highlighter, Output, translations, or live-sync behavior.

## What this adds

- A native Dashboard as the first screen when the Windows app launches.
- Separate Operator, Output, Highlighter, and Settings windows.
- Closing an individual module window leaves the Dashboard and other modules running.
- The local Node server starts automatically inside the Electron app; no separate Node.js installation is needed by the end user.
- The Output window can be moved to a second monitor. Settings also has an **Open Output on Second Display** action.
- A copyable LAN Output URL for vMix / OBS Browser Source.
- Session cache and uploaded backgrounds are written to Electron's user-data folder, not the read-only `app.asar` package.
- A Windows GitHub Actions workflow that builds both an NSIS `Setup.exe` installer and a portable `.exe`.

## Apply to the repository

1. Extract this ZIP into the root of `MCGI-Bible-Broadcaster-Pro`, replacing its `package.json` with the included one and adding `desktop/` plus `.github/workflows/windows-desktop-build.yml`.
2. Open PowerShell in the repository root and run:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\APPLY-DESKTOP-INTEGRATION.ps1
   ```

3. Install dependencies and test the desktop shell:

   ```powershell
   npm install
   npm run desktop
   ```

   Then create the Windows installer and portable executable with `npm run build`.

4. To build locally on Windows:

   ```powershell
   npm run build
   ```

   The outputs are written to `dist/`.

5. Alternatively, push the changes to GitHub. The **Build Windows Desktop App** workflow will build the installer and portable executable and upload them as a workflow artifact.

## vMix / OBS

Use the URL shown on the Dashboard or in Settings as the Browser Source:

`http://<LAN-IP-OF-THE-PC>:3300/output/output.html`

Keep the computer hosting the app and the vMix/OBS machine on the same local network. The native Output window is for the second monitor; vMix/OBS should use the LAN URL as a Browser Input.

## Notes

- Port `3300` is intentionally kept fixed to preserve the current system's LAN URLs. Close any other process already using port 3300 before launching the desktop app.
- The existing root `portal-home.html` and the web routes remain available to other devices on the LAN.
- Build artifacts are not generated by extracting this patch. They are produced by `npm run build` on Windows or by the GitHub Actions workflow.
- The repository's `package-lock.json` should be refreshed by `npm install` after applying the new `package.json`.

### Dashboard quick-access URLs
The Dashboard shows both the LAN URL for the Live Output and the LAN URL for the Highlighter Station. Each URL has its own Copy URL button. The Highlighter URL uses the detected LAN IPv4 address and the configured server port, for example `http://192.168.x.x:3300/highlighter/`. The local-only address is also exposed internally as `localHighlighterUrl` (`http://127.0.0.1:3300/highlighter/`).
